# 市场机会雷达 V1.2

新增按平台查看：闲鱼、小红书、拼多多、淘宝/天猫、京东、抖音、1688、知乎、哔哩哔哩，以及GitHub、维基百科。榜单、趋势与导出按所选平台过滤。完整用途与接入状态见[平台说明](PLATFORMS.md)。目前仅GitHub与维基百科自动更新，其他平台可导入记录，尚未接入自动采集。

商品与软件机会的观察工具，现已接入每日更新的公开真实数据，并保留个人导入与模拟演示。

**网页：https://yxt1017.github.io/market-opportunity-radar/**

## 数据与使用

- 默认「公开真实数据」：中文维基百科16个主题的每日阅读量，及6个GitHub软件项目的累计Star数。
- 「商品机会」「软件机会」按类别筛选；百科与GitHub指标分别排名。
- 每日北京时间11:23自动采集并重新发布。GitHub调度可能延迟；页面显示最近采集时间、实际观测日与失败来源。
- 初次GitHub快照不足以计算历史增幅，会显示积累中。百科可回填官方已公布的近期日记录。
- 「我的导入数据」只保存在当前浏览器，可手工添加、CSV导入导出；不上传GitHub。
- 「模拟演示数据」完全隔离，数值均为虚构。

这些公开指标是阅读与开发者关注信号，**不是闲鱼、小红书、拼多多的搜索量或销量**。观察对象来自固定清单，不是全网新热词发现。具体算法、来源定义、权限和停用方法见 [每日数据说明](DAILY_DATA.md)。

## 自动发布与维护

工作流：[Daily public data and Pages](https://github.com/yxt1017/market-opportunity-radar/actions/workflows/daily-public-data.yml)。支持定时、手动和代码更新触发。Pages发布源使用GitHub Actions。

配置观察对象：`config/public_watchlist.json`。采集脚本：`scripts/update_public_data.py`。网页：`docs/`。公开历史数据保留90天，来源错误不会被补零或模拟值覆盖。

## 原项目使用说明

# 📡 市场机会雷达 V1

零付费、本地运行的市场关键词线索分析工具。支持**统一候选榜、商品机会榜、软件机会榜、关键词历史曲线、数据源审计、CSV 导入导出、手工记录**。

> **最重要：这个版本没有连接闲鱼 / 小红书 / 拼多多的实时数据！** 演示区均为虚构记录。真实区仅展示你自己导入的原始观察。不会伪造全网搜索量或实际成交量。

## Windows 启动（推荐：零 Python 第三方依赖版）

1. 在电脑安装 [Python 3.10 或更高版本](https://www.python.org/downloads/windows/)，勾选 `Add Python to PATH`。
2. 解压项目到文件夹，双击 **`启动雷达.bat`**，它使用 Python 自带组件，不需要 pip 下载任何库。
3. 自动打开浏览器 `http://127.0.0.1:8501`。如果没有自动打开，手动输入这个网址即可。
4. 默认选中**真实数据区（初次无数据）**，切换左上角**模拟演示数据**可试看功能。
5. 在「导入数据」页上传 UTF-8 CSV，或手工添加一条观察记录，随后进入候选榜及历史趋势。

在 Mac/Linux 上运行：`python3 server.py`。

**可选高级界面**：双击 `启动雷达_Streamlit可选版.bat` 使用 Streamlit 版（需要首次联网安装 `streamlit` 和 `pandas`；两个界面共用同一个 SQLite 数据库，不可同时使用默认 8501 端口）。推荐优先使用零依赖版，Streamlit 界面没有在当前环境完成运行验证。

手机访问：当前为了保护本地记录，只绑定 127.0.0.1（Windows 本机）；手机无法直接访问。未来在增加鉴权与网络配置后再开放局域网访问。

## 数据从哪里来

- **官方授权导出/接口**：优先；但后台数据仅限其统计范围（例如本店），不代表全网。请自己核实授权范围、指标释义及可导出性。
- **人工公开观察**：例如自行记录搜索建议出现的位置、可见商品数量；不能推算真实搜索人数、销量。
- **第三方数据**：必须能说明采样方法、更新时间和来源；本程序只保存声明，不能验证第三方说法。
- **模拟样本**：只用于 UI 演示，SQLite 记录标记 `is_demo=1`，不能冒充真实数据。

**特别注意**：2026年10月7日生效的闲鱼社区法律声明明确限制未获许可的第三方自动化访问/抓取。本项目不包含闲鱼登录、爬虫、验证码绕过或任何非授权自动采集。

| keyword | 磁吸支架 | 词条 |
| opportunity_type | 商品 | 商品/软件（由你人工分类） |
| metric_type | shop_search_visitors | 原始指标代码，见下 |
| metric_value | 42 | 原始数值（不允许猜测） |

| source_scope | 店铺A·搜索访客 | 采样范围。保持每次一致 |
| source_url |  | 可追溯的链接（可留空） |
| notes | 仅本店 | 描述采样口径 |

### 可用指标

- `search_index`：相对搜索指数（不是搜索次数）
- `platform_searches`：平台披露的搜索次数（仅在实际有授权且清楚口径时使用）
- `shop_search_visitors`：本店搜索来源访问量（**不代表全站**）
- `search_result_count`：人工观察搜索结果数量（供给侧，不代表需求）
- `content_count`：人工观察内容数量（供给/内容侧，不代表需求）
- `suggestion_rank`：人工观察建议词位置（位置改善不等于搜索量增长）

`source_type`：`official_export` / `authorized_api` / `manual_observation` / `third_party_estimate`。演示内部使用 `demo`，真实区禁止导入此标记。

## 趋势怎么计算

把“最近观测日期”作为对齐日，对比 **最近7日均值** 和 **此前7日均值**：

`相对变化% = (近期均值 / 前期均值 - 1) × 100%`

前后每段至少2个观测才计算趋势，前期均值为0时显示不可计算。同一系列严格按 `平台+词+类别+指标+来源类型+来源名称+统计范围` 区分；不能把不同范围的数据拼接。`suggestion_rank` 仅计算位次改善的相对百分比，不代表真实搜索增长。

表格按“有上涨需求线索的平台数”与“可比需求线索变化中位数”排列候选复核顺序，**不是实际利润排行**，不同量纲的百分比也只能用于探索性筛选。仅有供给侧数据的词放在“仅有供给/位置线索”，不会被当成真实需求上涨。

注意：本版的7+7日窗口支持稀疏样本，若采集日不均匀仍可能有偏差。必须结合实际截图或后台数据人工复核后再做商业决策。

## 隐私和安全

- 默认只监听 `127.0.0.1`，不对局域网公开端口；也不会上传任何数据。
- 真实 CSV 写入 `data/opportunity_radar.sqlite3`（本地 SQLite 文件），演示数据以标签隔离。
- 删除 `data/` 文件夹会丢失所有导入记录，请先在“来源与质量”页导出备份。
- 不要在 CSV 中填入账号密码、Cookie、Token 等敏感认证信息。
